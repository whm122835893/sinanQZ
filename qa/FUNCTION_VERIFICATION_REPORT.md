## 五、发现的缺陷

### D-1【中危·安全】账户注销后仍可用密码登录并签发有效态
- **位置**：`sinan-nft-backend/app/controller/Auth.php` → `loginByPassword()`（约 339 行）与 `login()` 验证码分支，查询用户均**未过滤 `deleted_at`**。
- **现象**：用户完成注销（`nft_users.deleted_at` 已置位，`cancelAccount` 成功）后，`/api/auth/login` 密码登录仍返回 `code=0` + 新 token + 含 `uid/邀请码/实名状态`的 `userInfo`。
- **实际影响**：接口层 `JwtAuth` 会按 `deleted_at` 拒绝该 token 访问（实测 `user/profile` 返回 2001/1002），因此未造成数据泄露面扩大；但**登录入口本身不应放行已注销账号**，且响应泄露了 uid/邀请码，属于认证源端的一致性缺陷。
- **修复建议**：`loginByPassword` 与 `login` 验证码分支的用户查询统一加 `->whereNull('deleted_at')`，使注销账号在登录阶段即返回"未注册/禁用"，而非发 token 后再靠中间件拦截。

### D-2【中危·功能语义】发售日历未满足「历史发售记录 + 即将发售提醒」定义（已修复）
- **需求定义（用户澄清）**：发售日历应展示**历史发售的记录**（含已售罄/已结束）与**即将发售的提醒**（未来开售倒计时）。
- **原缺陷**：
  1. 数据源错误——`Calendar.vue` 复用首页的 `/api/collections/featured`，该接口 `where('status','<>','soldout')` 主动剔除售罄藏品，**历史发售记录根本无法呈现**；
  2. 深链/刷新不自动取数——组件未 `onMounted` 拉数，直接进入 `/#/calendar` 列表为空；
  3. 无倒计时提醒——待发售项仅一个静态"待发售"标签，无"距开售"倒计时。
- **修复**：
  - 后端新增 `GET /api/collections/calendar`（`Collections::calendar()`，`route/api.php` 注册在 `:id` 通配之前）：返回 `is_release=1` 且 `status<>'off'` 的全部发售藏品（**含 soldout 历史**），带 `saleTime/saleEndTime/stock/edition`；
  - 前端 `Calendar.vue` `onMounted` 自取数，按 `saleTime/saleEndTime/stock/now` 分段：**即将发售**（待发售带每秒刷新的"距开售 D天 HH:MM:SS"倒计时 + 发售中）按开售时间升序、**历史发售**（已售罄/已结束）倒序；含加载态与空态。
- **验证**：临时置 `9980=soldout`、`9979=off`、`3=未来开售` 造数后——`/calendar` 返 11 条含 9980、排除 9979；`/featured` 仍 10 条不含 9980（历史语义不误伤首页）；页面渲染出"即将发售 + 距开售倒计时 + 历史发售/已售罄 E2E盲盒"；造数已全部还原（基线 3/9979/9980 状态与计数一致）。`featured` 接口本身未改动，回归 `detail`/`featured` 均正常。

### 记录性（非缺陷）
- `sit_h1_oversell` 的 **H1-3s「梯度负载连接错误为零」** 未过：Windows `php -S` 单线程，200 并发瞬时打满连接层，出现连接失败计数。这是**本地开发服务器并发极限**，非业务问题——**同批正确性断言全部通过**：无超卖（sold+locked≤edition 恒成立）、支付/取消无双重处理、持仓=完成量、serial 全局唯一、资金守恒、限购并发恰放行 N 笔、零死锁。生产以 php-fpm/网关扩容 worker 即消除。
- E2E/SIT 脚本在 PHP 8.5 下打印 `curl_close() deprecated` 提示；`sit_full_audit` 在未重置的脏库上首跑有外键清理告警——均为脚本环境噪声，先跑 `sit_baseline_reset` 后 0 告警、全绿。
